# AutoBotHtsH

HtsH(한국투자증권 OpenAPI 개인 HTS - 시세 조회와 수동 주문 창)의 화면에 AutoBotH(r003 자동매매 봇 뷰어·원격 제어)의 기능을 합친 Windows 앱입니다.

## 화면

- HtsH와 같은 **여러 창(MDI) 작업공간**입니다. 창을 끌어 옮기고, 크기를 바꾸고, 최소화·최대화·정렬할 수 있습니다.
- **HTS 창** (툴바 `+ 차트`, `+ 현재가` …): 차트, 현재가, 종목정보, 관심종목, 순위, 지수, 뉴스. KIS 앱키로 로그인하거나 데모 모드로 씁니다.
- **봇 창** (툴바 `봇 ▾`): AutoBotH의 탭 11개가 창 하나씩입니다. 같은 종류는 하나만 열리고, 다시 고르면 열린 창으로 이동합니다.
  - 운영: 제어, 데이터 작업, 수집기, 파이프라인
  - 분석: 종목 보드, 타임라인, **봇 차트**, 보유 현황, 매매 결과, 가상 매매
  - 시스템: **봇 설정·연결**
- 이름이 겹치는 기능은 봇 쪽에 `봇` 을 붙였습니다(봇 차트 = AutoBotH 차트 탭, 봇 설정·연결 = AutoBotH 설정·연결 탭).
- 툴바 아래 한 줄은 AutoBotH 상태 줄입니다(연결 · 봇 실행 상태 · 날짜 · 수신/경고/시장/감시/조건).

## 설정과 데이터

- 앱 폴더: `%APPDATA%\autobothtsh` (HtsH / AutoBotH와 따로).
- 처음 실행할 때 가져오는 것:
  - AutoBotH 연결 설정. SSH 비밀번호와 프록시 비밀번호는 앱마다 암호화 키가 달라 가져오지 않으니 **봇 설정·연결**에서 다시 입력하세요.
  - HtsH 관심종목(`watchlist\watchlist.json`).
- KIS 앱키는 HtsH와 따로 저장됩니다. 처음에 한 번 로그인하세요.
- 관심종목 picks 파일(`_YYYYMMDD_picks.txt`)은 `%APPDATA%\autobothtsh\watchlist\` 에 두면 MMDD 탭으로 등록됩니다.

## 게스트 모드 (인증키 없는 PC)

KIS 인증키가 없는 PC에서도 실제 시세로 관심종목(목록 / 타일), 차트, 현재가, 종목정보, 순위, 지수, 뉴스 창을 쓸 수 있습니다. 인증키로 로그인한 다른 PC의 AutoBotHtsH(호스트)가 시세 조회를 대신해 줍니다.

| | 할 일 |
|---|---|
| 호스트 PC (KIS 로그인) | ☰ → 설정 → **게스트 접속 허용**: 포트(기본 47800)와 암호(8자 이상)를 정하고 켭니다. Windows 방화벽 창이 뜨면 허용합니다. 화면에 나오는 주소(예: `192.168.0.10:47800`)를 게스트 PC에 입력합니다 |
| 게스트 PC | 로그인 화면의 **게스트 접속**에 호스트 주소와 암호를 넣고 `게스트로 접속`. 저장해 두면 다음부터 `저장된 호스트로 접속` 한 번이면 됩니다 |

- 게스트는 앱의 조회 기능만 쓸 수 있습니다. 호스트가 받아 주는 호출은 화면이 쓰는 조회 목록과 같고, 앱에는 주문 코드가 없습니다.
- 호스트 PC의 앱이 켜져 있고 KIS에 로그인되어 있어야 합니다. 조회는 호스트의 KIS 호출 한도를 함께 씁니다.
- 게스트에는 실시간 연결이 없어 창들이 몇 초 간격으로 갱신됩니다. 관심종목과 창 배치는 게스트 PC에 따로 저장됩니다.
- 암호는 양쪽 PC에 Windows 계정으로 암호화해 저장합니다. 암호를 5번 틀린 주소는 1분 동안 막힙니다.
- 통신은 암호화되지 않은 HTTP입니다. 같은 공유기 안에서 쓰는 용도이며, 집 밖에서 쓰려면 본인의 HTTPS 터널 주소(`https://...`)를 호스트 주소로 넣으세요. 포트를 인터넷에 그대로 열지 마세요.
- 본인 PC끼리 쓰는 기능입니다. KIS 시세를 다른 사람에게 제공하는 용도로 쓰면 안 됩니다.

**다른 장소에서 접속 (회사 ↔ 집)**: 호스트 화면에 나오는 주소는 공유기가 준 내부 주소라 같은 네트워크 안에서만 통합니다. 다른 곳에서 쓰려면 아래 중 하나가 필요합니다.

| 방법 | 게스트 PC에 넣는 주소 | 비고 |
|---|---|---|
| VPN (예: Tailscale) | 호스트의 VPN 주소 `100.x.x.x:47800` | 두 PC에 같은 계정으로 설치. 통신이 암호화되고 인터넷에 포트가 열리지 않음. 호스트 화면의 주소 목록에 VPN 주소도 같이 나옴 |
| HTTPS 터널 (예: Cloudflare Tunnel) | `https://<내 도메인>` | 호스트 PC에서 터널을 `http://localhost:47800` 으로 연결. 인터넷에 공개되는 주소이므로 암호를 길게(16자 이상) 정하고, 가능하면 터널 쪽 접근 제한도 함께 사용 |
| 공유기 포트포워딩 | 공인 IP:포트 | 권하지 않음 - 암호와 시세가 암호화 없이 인터넷을 지나감 |

터널을 거치면 모든 요청이 호스트 PC 자신(127.0.0.1)에서 온 것으로 보이므로, 암호 오류 차단과 게스트 수는 터널이 알려 주는 접속 주소(`CF-Connecting-IP`, `X-Forwarded-For` 의 마지막 값) 기준으로 셉니다.

## 바닥 반등 초입 감시

관심종목 창에서 이름이 **TEST** 인 탭의 종목을 1분봉으로 감시하다가, 급락 뒤 반등 초입 조건이 맞으면 화면 우하단에 항상 위 팝업을 띄웁니다. 감지와 알림만 하고 주문은 내지 않습니다.

- **쓰는 법**: KIS 앱키로 로그인하고 관심종목 창에 `TEST` 탭을 만들어 종목을 넣으면 됩니다(탭 더블클릭 = 이름 바꾸기). 탭은 5분마다 다시 읽습니다. 데모 모드에서는 감시하지 않습니다.
- **설정**: ☰ > **반등 감시 설정**. 감시 켜기/끄기, 감시할 탭(고르기·만들기), 그 탭의 종목 추가·삭제, 아래 조건의 모든 값, 운영 시간, 알람 테스트, 설정·기록 폴더 열기를 한 창에서 합니다. 저장하면 다음 분부터 적용됩니다.
- **상태**: 제목 줄의 `반등 감시 TEST · N종목` (표시만). 마우스를 올리면 마지막 순회 시각과 오류가 보입니다.
- **동작**: 매분 2초에 탭의 종목을 차례로 조회해(첫 조회 뒤에는 종목당 1회 호출) **완성된 봉**만 판정합니다. 같은 종목은 30분 동안 다시 알리지 않습니다. 팝업의 `열기` 는 그 종목을 앱의 창들에 띄웁니다.
- **운영 시간**: 평일 KRX 09:00~15:30, NXT 프리 08:00~08:50, NXT 애프터 15:40~20:00. NXT 시간에는 NXT 거래 종목만 조회합니다.
- **파일** (`%APPDATA%\autobothtsh\rebound\`, 설정 창의 `설정·기록 폴더` 버튼):
  - `config.json`: 설정 창이 쓰는 파일. 직접 고쳐도 다음 분부터 반영됩니다. 지우면 기본값으로 다시 만들어집니다.
  - `detections_YYYYMMDD.csv`: 감지 내역 전체(시각, 종목, 지표값, 점수, 알림 여부, 고점 낮아짐 판정, 알림을 안 보낸 이유 `suppressed` = `lower_high` 또는 `cooldown`). 이전 버전이 만든 같은 날 파일이 있으면 그 파일은 그대로 두고 `detections_YYYYMMDD_2.csv`(그것도 형식이 다르면 `_3` ...)에 이어 씁니다.
- **모의투자 접속**은 지난 날짜 분봉을 받을 수 없어, 당일 봉이 200개 쌓인 뒤부터 판정합니다.

### 알림 히스토리와 미확인 알람

- 설정 창의 **히스토리** 탭에 지금까지 뜬 알림이 최신순으로 쌓입니다(최대 500건, `rebound\history.json`). 항목을 누르면 팝업에 나왔던 내역(조건, 가점, 지표)이 표시됩니다. 모두 확인, 삭제, 팝업으로 다시 보기, 종목 열기를 할 수 있습니다.
- **팝업 유지 시간**(설정 탭 > 알림, 기본 60초, 0 = 닫지 않음)이 지나 저절로 닫힌 알람은 미확인으로 남고, 제목 줄에 `미확인 알람 N`이 표시됩니다. 누르면 히스토리 탭이 열립니다.
- 팝업을 직접 닫거나(✕) `열기`를 누르면, 또는 히스토리에서 항목을 누르면 확인 처리됩니다.

### 카카오톡으로 알림 보내기

알림 요약(종목, 봉 시각, 가격·등락률, 가점, 주요 지표)을 본인 카카오톡 "나와의 채팅"으로 보냅니다. 카카오 디벨로퍼스에 본인 앱을 하나 만들어야 합니다(무료, 검수 없음).

1. <https://developers.kakao.com> 에 본인 카카오 계정으로 로그인 → **앱** → **앱 추가**. 이름과 회사명은 아무 값이나 됩니다.
2. **앱 → 플랫폼 키 → REST API 키**: 키 값을 복사합니다. 같은 화면의 **리다이렉트 URI**에 `http://localhost:5000/oauth` 를 등록합니다. 이 주소로 실제 접속하지는 않습니다(앱이 주소가 바뀌는 순간을 잡아 인가 코드를 읽습니다).
3. 같은 화면의 **클라이언트 시크릿**이 "사용함"이면 그 값도 복사합니다. "사용 안 함"이면 필요 없습니다.
4. **카카오 로그인 → 사용 설정**: 상태를 ON 으로 바꿉니다.
5. **카카오 로그인 → 동의항목 → 카카오톡 메시지 전송(talk_message)**: "선택 동의"로 설정합니다.
6. (선택) 메시지의 `종목 보기` 버튼이 열리게 하려면 **앱 → 제품 링크 관리 → 웹 도메인**에 `https://m.stock.naver.com` 을 등록합니다. 등록하지 않아도 메시지는 옵니다.
7. 앱에서 ☰ > 반등 감시 설정 > **카카오톡** 탭: REST API 키(와 시크릿)를 넣고 `앱 정보 저장` → `카카오 로그인`(로그인 후 "카카오톡 메시지 전송" 동의) → `테스트 메시지 보내기`.
8. 테스트 메시지가 오면 `알림을 내 카카오톡으로 보내기`를 체크하고 `저장`.

| 오류 | 원인과 해결 |
|---|---|
| KOE004 | 카카오 로그인이 꺼져 있음 → 4번 |
| KOE006 | 리다이렉트 URI가 등록 값과 다름 → 2번 (끝의 `/`, http/https, 포트까지 같아야 함) |
| KOE010 | 클라이언트 시크릿 불일치 → 3번 (켜져 있으면 입력, 꺼져 있으면 `시크릿 지우기`) |
| KOE101 | REST API 키가 아님(네이티브·JavaScript·어드민 키를 넣음) → 2번 |
| KOE205 | talk_message 동의항목 미설정 → 5번 |
| -402 | 로그인 때 "카카오톡 메시지 전송"에 동의하지 않음 → `다시 로그인` |
| KOE322, -401 | 로그인 만료 → `다시 로그인` |

- 키, 시크릿, 로그인 토큰은 `rebound\kakao.json`에 이 PC의 Windows 계정으로 암호화해 저장합니다. 다른 PC로 복사하면 쓸 수 없어 그 PC에서 다시 설정해야 합니다.
- 로그인은 약 2개월 유지되고 메시지를 보낼 때마다 자동으로 연장됩니다. 2개월 넘게 알림이 한 번도 없었다면 다시 로그인해야 합니다.
- 전송 결과는 히스토리의 각 항목에 `톡`(초록 = 전송됨, 빨강 = 실패와 이유)으로 표시됩니다.

### 감지 조건

필수 조건 6개를 모두 충족하고 가점이 `bonus.minScore`(3점) 이상이면 감지입니다. 돌파는 급락 봉 뒤, 최근 `lookback`(25)봉 안에 있어야 합니다.

| | 필수 조건 | 설정 항목 |
|---|---|---|
| A | 최근 40봉 안에 급락 봉: 전봉 대비 -0.8% 이하 또는 아랫꼬리가 몸통의 2배 이상, 거래량이 앞 60봉 평균의 3배 이상, 그 뒤 저가가 더 낮아지지 않음. 급락 봉까지의 낙폭(앞 60봉 최고가 -> 급락 봉 저가)이 8%를 넘으면 악재성 급락으로 보고 제외. 급락 봉이 없어도 당일 첫 봉 시가가 전봉 종가보다 1.5% 이상 낮게 시작(갭 하락)했고 그 첫 봉이 40봉 안에 있으면 급락 선행으로 인정(급락 봉 = 시가 이후 최저가 봉, 거래량 조건 없음) | `plunge.*` (`fallWindow`, `maxFallPct`, 0 = 제한 없음, `gapPct` 0 = 끔) |
| B | RSI가 시그널을 상향 돌파, 최근 5봉 중 3봉 이상 시그널 위, 현재 봉도 시그널 위, 현재 RSI 45~68 | `recent`, `recentMin`, `requireCurrentAbove`, `rsi.*` |
| C | MACD가 0선 아래에서 시그널을 상향 돌파한 뒤 계속 위, 오실레이터 3봉 연속 확대 | `macd.oscRising` |
| D | DI+가 DI-를 상향 돌파, 최근 5봉 중 3봉 이상 위, 현재 봉도 위 | `recent`, `recentMin`, `requireCurrentAbove` |
| E | MA5가 MA20을 골든크로스, 종가 > MA5 > MA20 | |
| F | MA5 각도 14° 이상. 각도 = atan(1봉당 % 변화 × `k`), 3봉 전 MA5와 비교 | `angle.*` |

**장 경계 제외** (`edge.openMin`, `edge.closeMin`, 기본 15분): 각 운영 시간대의 처음 15분과 마지막 15분(KRX 09:00~09:14, 15:16~15:30, NXT 애프터도 같은 방식. NXT 프리마켓 08:00~08:50은 짧아서 `edge.preOpenMin`, `edge.preCloseMin` 기본 5분을 따로 씀: 08:00~08:04, 08:46~08:50)에는 감지하지 않고, 그 시간의 봉은 급락 봉으로도 치지 않습니다. 개장·마감 때는 거래량이 원래 몰려 "평균의 3배" 조건이 저절로 충족되기 때문입니다. 0으로 두면 끕니다.

가점(각 1점): ADX가 내려왔다가 최근 4봉 안에 바닥을 찍고 반등, 종가가 MA60/MA120을 돌파했거나 0.2% 이내, 볼린저 폭이 급락 때보다 좁고 종가가 중심선 이상, 전환선 > 기준선이고 종가가 구름 안이나 위, MACD가 0선 근처(가격의 0.05% 이내)이거나 최근 3봉 안에 0선 돌파, 반등 구간 평균 거래량이 급락 봉보다 적음. VWAP 위치는 조건이 아니고 팝업에 표시만 합니다.

**고점 낮아짐 (우하향) 확인** (`lowerHigh.*`, 2026-11-24): 급락 봉 전의 마지막 두 전고점(H1, H2)과 급락 다음 봉부터의 반등 고점(현재)이 차례로 낮으면(H1 > H2 > 현재) "고점 낮아짐"으로 팝업·히스토리의 **추세 구조**, 카카오톡 요약, 감지 기록에 표시합니다.

- 전고점: 좌우 `pivotBars`(5)봉보다 높은 봉(같은 고가가 이어지면 마지막 봉 하나로 봄). 판정 봉과 같은 날·같은 운영 시간대, 앞 `rangeBars`(150)봉 안에서만 찾습니다. 두 개가 안 되면 "판정 불가"이고 알림은 그대로 갑니다.
- 낮아짐: H1 -> H2, H2 -> 현재 각각 `minDropPct`(0.2%) 이상 **그리고** `minTicks`(2)틱 이상 낮을 때.
- RSI 상승 다이버전스: 급락 저점이 H1~H2 사이 최저점보다 낮은데 그 봉의 RSI 는 더 높음. 반등 초입에 흔한 신호라 함께 표시합니다(기준 사례 448900 11/20 14:55 도 고점 낮아짐 + 다이버전스).
- `lowerHigh.block`(기본 끔): 켜면 고점 낮아짐 감지는 알림(팝업·카톡)을 보내지 않고 감지 기록에만 남깁니다(`suppressed` = `lower_high`, 재알림 대기 시간도 쓰지 않음). `divExempt`(기본 켬)이면 다이버전스가 있는 경우는 그래도 알립니다. 수집 데이터 17거래일 재생에서는 효과가 아직 확실하지 않아(Codex 검토 "표시 먼저") 기본은 표시만 합니다.

지표는 차트와 같은 코드(`src/shared/indicators.ts`)로 계산합니다. 기본값은 차트 기본 설정과 같습니다(RSI 14 / 시그널 6, MACD 12·26·9, DMI 14, 볼린저 20·2, 일목 9·26·52, 계산 방식 `mts`). 차트 설정을 바꿨다면 `config.json` 의 `indicator` 도 같이 바꾸세요. `rsiMethod` / `adxMethod` 를 `wilder` 로 두면 Wilder 방식입니다.

### 리플레이

저장된 1분봉(CSV `date,time,open,high,low,close,volume` 또는 앱의 차트 캐시 `chartcache\real_<코드>_min_.json`)을 봉 하나씩 흘려보내 감지 시점을 출력합니다.

```
npm run replay -- tests/rebound_448900_20261120.csv --from 13:00 --to 15:20
npm run replay -- <파일> --date 20261120 --explain 14:55      # 그 봉의 조건별 판정
npm run replay -- <파일> --all                                # 필수 조건만 충족한 봉도 표시
npm run replay -- <파일> --config <config.json> --set angle.min=15 --set recentMin=4
```

## AutoBotH와 함께 쓸 때

- 봇 실행(r003), 감시 프로세스(r020), 데이터 작업(r021), 틱 수집기(g011)는 서버 쪽 잠금 파일을 쓰므로 어느 앱에서 시작해도 한 번만 실행됩니다.
- 이 PC(로컬 모드) 스케줄러(틱 수집기 확인 / 장 마감 작업 / 라즈베리파이 감시목록 복사)는 두 앱 중 **하나만** 돌립니다.
  - 공유 파일: `%APPDATA%\autoboth-shared\scheduler.json`
  - 다른 앱은 대기하고, 스케줄러 메시지에 어느 앱이 실행 중인지 표시합니다.
  - 마지막 장 마감 작업 날짜도 공유해서 같은 날 두 번 실행하지 않습니다.

## 소스 구성

| 위치 | 내용 |
|---|---|
| `src/main`, `src/preload`, `src/renderer`, `src/shared` | HtsH (v0.1.5_002 기준) + 통합 코드 |
| `src/bot/{main,preload,shared,renderer/src}` | AutoBotH (v2.3.32_003 기준) 사본. 상대 경로 구조를 그대로 둠 |
| `src/main/importOnce.ts` | 첫 실행 때 설정 가져오기 |
| `src/shared/rebound.ts` | 바닥 반등 감지(순수 함수)와 설정 기본값 |
| `src/shared/reboundReplay.ts`, `scripts/rebound-replay.cjs` | 리플레이 |
| `src/main/reboundPoller.ts`, `src/main/reboundAlert.ts` | 매분 순회, 팝업·알림음·감지 기록 |
| `src/renderer/src/windows/BotWindow.tsx` | 봇 화면을 창으로 띄우는 부분, 상태 줄, 확인 창 |
| `src/bot/renderer/src/styles.scoped.css` | AutoBotH 스타일을 `.bot-root` 안으로 한정한 생성 파일 (`npm run scope-css`) |
| `tests/` (HtsH), `tests/bot/` (AutoBotH) | vitest |

AutoBotH나 HtsH를 고친 뒤 이 앱에도 반영하려면 해당 파일을 같은 위치로 복사합니다. AutoBotH의 `styles.css`를 바꿨다면 `npm run scope-css` 를 실행합니다. 통합 때 바꾼 파일은 각 파일 맨 위 Update log의 `AutoBotHtsH` 항목에 적혀 있습니다.

## 명령

```
npm install
npm run dev        # 개발 실행
npm start          # 빌드 후 실행
npm test           # vitest
npm run replay -- <분봉 파일>   # 바닥 반등 감지 리플레이
npm run typecheck
npm run dist       # 설치 파일 (dist/)
```

화면 시험: `AUTOBOTHTSH_USERDATA=<빈 폴더>` 로 실행하면 그 폴더를 앱 폴더로 쓰고 아무 설정도 가져오지 않습니다(봇 연결·스케줄러 없음). `HTSH_DEMO=1` 은 데모 모드로 시작합니다.
