## 3. 시점 규칙 (look-ahead 방지 - 백테스트와 같은 정의)

- 1분봉 m(시작 시각 라벨, 예: 10:20 봉 = 10:20:00~10:20:59)의 판정 시각 `T(m)` = m 의 끝(10:21:00).
- 판정에 쓰는 3분봉 = 버킷 `(m+1)//3 - 1` (09:00 기준 분 번호), 60틱봉 = 마지막 체결 시각이 `T(m)` **보다 앞선** 마지막 완성봉.
- **"지금 최신 상태"가 아니라 봉 식별자로 결합**한다. worker 는 처리하지 않은 1분봉 m 을 시간 순서로 하나씩 평가하고,
  각 m 마다 위 규칙의 3분봉·60틱봉만 쓴다. 폴링이 밀려 더 새 봉이 이미 만들어져 있어도 쓰지 않는다.
- **확정 정책 하나만 쓴다: 1분봉 m 과 3분 버킷은 끝 시각 + 5초(벽시계, r028 `time_bar_delay_s` 와 같은 값)에 확정한다.**
  확정 시각 `C(m) = T(m) + 5초`. 판정·기록은 C(m) 이후에만 한다.
- 체결 시각은 KIS 체결시각(trade_time, 초 단위)으로 봉에 배정하고, 같은 초 안에서는 파일 순서를 유지한다(백테스트의 stable sort 와 같음).
- **확정된 봉은 바꾸지 않는다.** C(m) 이후 들어온 체결인데 체결시각이 이미 확정된 봉 구간이면 실시간 봉에는 넣지 않고 `late_prints` 로 센다(STATS).
  사후 리플레이는 파일 전체를 정렬해 다시 만들고, 실시간 봉과 다른 봉 수를 `replay_divergence` 로 보고한다.
- 빈 분(체결 없는 분)은 봉을 만들지 않는다(백테스트와 같다). 직전 1분봉과 분 번호가 이어지지 않으면 `gap=true` 를 기록한다.

## 4. 워밍업과 재시작

| 대상 | 소스 (순서대로) | 준비 조건 | 준비 전 |
|---|---|---|---|
| 1분·3분 지표 | ① 전 거래일 1분 파일 `runtime/data/<전일>/<code>_*_10s.txt` (raw_bar=1, 백테스트와 같은 소스) ② 없으면 전일 틱 파일 전체를 1분봉으로 집계 ③ 둘 다 없으면 당일 봉만 | 1분 120봉, 3분 40봉 이상 | 평가는 하되 `ready=false` 로 기록, 신호·비교 표본에서 제외 |
| 60틱 | 전일 틱 파일 전체(KRX 정규장) | 60틱 40봉 | c2 = null |
| 당일 봉 | 당일 틱 파일을 **처음부터 끝까지** 다시 읽어 세션 시작 기준으로 봉 생성 (`TickFileTail` 의 4MiB 꼬리 읽기만 쓰지 않음) | - | - |

- 모든 행에 `warm_src` (`minute` / `tick` / `none`) 를 기록한다. **호스트별 소스 가용성은 확인되지 않았다**(노트북은 runtime/data 1분 파일이 있음,
  Pi 는 g001 수집 여부 미확인). 구현 전에 두 호스트에서 전일 1분 파일 존재를 확인하고, 없으면 ② 로 동작한다.
  백테스트 일치 분석은 `warm_src=minute` 행만 쓴다.
- 차이로 명시하는 점: b_build 는 연속된 평가일이면 여러 날을 이어 계산한다. r029 는 전 거래일 1일만 쓴다(3분 지표 수렴에는 충분, 수치 테스트로 차이 크기 확인).
  전일 종가 기준 차이: r029 는 **달력상 직전 거래일**의 마지막 1분 종가를 쓴다. b_build 는 **불러온 직전 날**(그 종목 파일이 있는 날)이라
  중간에 빠진 날이 있으면 더 이전 날 종가가 된다. 이 차이는 의도한 것이다(실시간에는 직전 거래일이 맞다). 일치 분석에서 r3 불일치로 따로 센다.
  기준이 없으면 r3 는 통과다 - b_eval 의 위험 필터도 `day_ret` 이 NaN 이면 통과시킨다(같은 규칙).
- r003 재시작, 감시 목록 재진입 때도 당일 파일 전체로 다시 만든다. 그래서 60틱 경계가 세션 시작 기준으로 항상 같다.
  다시 읽기는 worker 스레드에서 하며, 6절 측정 기준(꼬리 지연 포함)을 넘으면 기본값을 off 로 유지한다.
- **체크포인트**: `runtime/live/reversal_shadow_state_YYYYMMDD.json` 에 cfg 해시, 종목별 마지막 평가 1분봉, 종목별 마지막 신호 시각(쿨다운)을 저장한다.
  10분마다와 close 때 임시 파일 + rename 으로 원자적으로 쓴다. 재시작 시 cfg 해시가 같으면 복구, 다르면 무시(새 코호트).
  비정상 종료로 최대 10분 커서를 잃으면 그 구간을 시간 순서로 다시 평가한다. 다시 평가할 때 **이미 기록된 이벤트도 쿨다운 상태는 갱신**하고
  기록만 건너뛴다. 중복 판단 키는 `(cfg, code, bar, ev)` 이다(설정이 바뀐 새 코호트의 기록은 막지 않는다).

## 5. 기록 형식

`runtime/live/reversal_shadow_YYYYMMDD.jsonl` (한 줄 = 한 이벤트). 모든 행에 `cfg` = 설정값 해시(8자리)와 `ready`, `gap` 포함.
시각 필드: `bar` = 판정한 1분봉(시작 시각 라벨), `t` = 확정 시각 C(m) = 봉 끝 + 5초, `wrote` = 실제 기록 시각(밀림 확인용).
- `SIGNAL`: 필수 조건 모두 통과. 조건별 값·통과 여부 전부, `conf`, `suppressed`(쿨다운으로 억제된 원신호도 기록, 플래그로 구분),
  `held`(set_watch blocked 의 POSITION/PENDING_ORDER), `real_submit_within_60s`(r003 `_entry_note("submit")` 훅을 r029 에도 전달해 사후 채움)
- `NEAR`: s1~s4 통과 + 1분 진입 실패. **같은 종목·같은 3분 버킷에서 첫 1건만** 기록(용량 상한: 종목당 3분에 1건, 40종목 x 105 = 하루 최대 약 4,200줄)
- `STATS`: 10분마다 종목 수, 평가 수, 조건별 실패 횟수, worker 지연(초), 큐 드롭, 오류 수, `late_prints`
- `WATCH`: 종목이 감시에 들어오거나 나갈 때, ready 가 바뀔 때 (`on`/`off`/`ready`/`unready`, 시각). 사후 무작위 기준의 자격 구간을 이것으로 복원한다
  (감시 전 구간을 실시간 관측 신호로 취급하지 않기 위함)

## 7. 사후 평가 (지금 고정, 결과를 본 뒤 바꾸지 않는다)

도구: `data_simulation/g038_reversal_shadow_report.py`.

두 가지 결과를 따로 계산한다. 비용은 둘 다 수수료 0.015% x 2 + 세금 0.20% (곱셈식, b_build `net`).

**(가) 실행 가능 결과 - 주 지표, 틱 기준**
- 매수: 확정 시각 C(m) 이후 체결시각을 가진 첫 체결가 + 1틱. 그 체결 이후의 체결만 청산 판정에 쓴다(매수 전 고가·저가 미사용).
- 익절: 체결가 >= 익절가인 첫 체결 -> 익절가에 체결(지정가). 손절: 체결가 <= 손절가인 첫 체결 -> 그 체결가 - 1틱. 같은 체결에서 둘이 동시일 수 없다(가격 하나).
- 시간 청산: 매수 시각 + 60분(또는 15:20 중 이른 시각) 이전 마지막 체결가. 고정 시간 결과(3/5/10/30분)도 **경과 시간** 기준 마지막 체결가.
- 매수 후 체결이 하나도 없으면 `unresolved` 로 따로 세고 평균에서 뺀다(비율 보고).

**(나) 백테스트 일치 결과 - 보조, 1분봉 기준**: b_build 규칙 그대로(다음 1분봉 시가 + 1틱, 1분 OHLC, 손절 -1틱, 시가 갭, 같은 봉 손절 우선·시가 익절 예외, 봉 개수 기준 시간). 구현 차이 점검용.

**무작위 기준**
- 자격: 같은 날 WATCH 기록상 감시 중 + ready=true + gap=false + 위험 필터(r1~r3) 통과인 (종목, 1분봉).
- 순서: 자격 -> 추출 -> 쿨다운. 날짜별로 시드 `crc32(f"{day}-20261117")` 로 비복원 추출, 개수 = min(3 x 그날 신호 수, 자격 수). 부족하면 자격 전부.
  추출 후 신호와 같은 쿨다운(종목별 10분)을 적용하고 같은 (가) 규칙으로 결과를 계산한다.
- 신호가 0건인 날은 차이 계산에서 빠진다(날짜 수에는 보고).

**채택 판정**
- 표본: 쿨다운 후, ready=true, gap=false 인 SIGNAL.
- 날짜별 차이 `d_day` = 그날 신호 평균 - 그날 무작위 평균 (신호 1건 이상인 날, 날짜 가중 동일). `t = mean(d) / (sd(d) / sqrt(n_days))`, 단측.
- 판정 시점: **30거래일 그리고 신호 300건**이 모두 찼을 때(먼저 보지 않는다). 60거래일까지 못 채우면 그 시점.
- 최대 2회 판정(1회 연장)이므로 두 번 모두 **t >= 2.3** 을 쓴다(두 번 보는 것에 대한 보정).
- 채택: 신호 순손익 평균 > 0, 차이 평균 >= +0.15%p, t >= 2.3 셋 다. -> 실매수 연결은 **별도 설계**로 검토(이 shadow 로는 매수하지 않음).
- 폐기: 차이 평균 <= 0 또는 신호 순손익 평균 <= -0.2%. -> shadow 끄기.
- 그 외(불확실): 같은 설정으로 30거래일 1회 연장 후 같은 기준으로 최종 판정. 연장 후에도 채택이 아니면 폐기.
- 설정·코드가 바뀌면(cfg 해시 변경) 그날부터 새 코호트로 처음부터 센다.
- 보조 분석(판정에 쓰지 않음): conf 0/1/2, c2 null, NEAR 실패 사유, 같은 날 실매수·r028 shadow BUY 와의 비교.

리플레이 일치 확인(구현 직후 1회 + 판정 때): 과거 틱·1분 파일로 r029 를 다시 돌려 같은 날 b_build 신호와 (종목, 봉) 단위로 비교. 불일치율과 원인을 문서에 남긴다.
