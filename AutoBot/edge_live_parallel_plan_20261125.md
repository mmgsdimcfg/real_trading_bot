# Edge AI 실주문 병행 (규칙 매매와 함께) - 계획 (2026-11-25, 초안 -> Codex 검토)

사용자 요청(2026-11-25): 앱 제어 탭 "Edge AI 매매"의 "가상 매수" 체크를 풀면 Edge AI 신호로 **실제 주문**을 낸다.
규칙 매매도 같이 돈다(둘 다 실주문). 체크돼 있으면 지금처럼 가상 매매.

## 0. 현재 상태 (코드 확인)

- 매수 조건 목록은 전역 설정 하나로 정해진다: `r005.active_buy_conditions()` - `TRADING_STRATEGY_MODE` 가 edge 면 `EDGE_BUY_CONDITIONS`
  (_001~_008 운영 안전 + `_e09_edge_ai_signal` + _023~_025), 아니면 규칙 조건. 둘을 같이 평가하는 경로가 없다.
- 매도 조건도 전역: `r006.active_sell_conditions()` - AUTO_SELL_MODE(stop_only / off)가 최우선, 그다음 EXIT_ENGINE_MODE live(적응형, edge 제외),
  edge 면 `EDGE_SELL_CONDITIONS`(_e10 익절 / _e11 손절 / _e12 시간 상한). 포지션이 어느 방식으로 산 것인지 구분하지 않는다.
- r003 종목 루프(7520~7633행): 보유면 `evaluate_sell_conditions`, 아니면 `check_buy_conditions` 한 번 -> 승인 시 `place_buy_order`.
- 가상 매매 러너 r022(`EDGE_ONLY_MODE=paper`)는 주문 없이 기록만. `TRADING_STRATEGY_MODE=edge` 일 때는 러너를 만들지 않는다.
- 수량: `_023_affordable_buy_qty` -> `MAX_ORDER_AMOUNT_KRW`(50만원) 예산. Edge 전용 예산은 없다.
- 실계좌 설정(live_overrides): TRADING_STRATEGY_MODE=normal, EDGE_ONLY_MODE=paper, EDGE_ONLY_LOG_ONLY=false, AUTO_SELL_MODE=all, MAX_OPEN_POSITIONS=10.
- 봇 주문은 `_order_cash` 에서 r023 체결 장부에 등록된다(방식과 무관하게 "봇 몫").

## 1. 실무 판단 (트레이너 관점) - 먼저 읽을 것

- 이 방식의 검증 결과는 지금까지 모두 손실이다: g029 과거 재생(2026-08-14~11-11, 58일) 거래당 -0.44 ~ -0.62%,
  65일 OOS 재생·회귀 실험도 왕복 비용(약 0.5%)을 넘지 못함, 11/20 가상 매매 청산 28건 중 손절 24건.
- 그래서 실주문은 "수익 기대"가 아니라 "실제 체결·슬리피지를 작은 금액으로 확인"하는 단계로 설계한다:
  1회 금액·동시 보유·하루 횟수·하루 손실에 Edge 전용 한도를 두고, 한도에 닿으면 그날 Edge 신규 매수를 멈춘다.
- 원칙: Edge 가 산 포지션은 Edge 규칙으로만 판다. 규칙 매매가 산 포지션은 규칙으로만 판다. 한 종목을 두 방식이 같이 들지 않는다.

## 2. 설계

### 2-1. 설정 키 (r001, r016 set / get)

| 키 | 기본 | 뜻 |
|---|---|---|
| `EDGE_LIVE_ORDERS` | False | True = Edge AI 신호로 실주문(규칙 매매와 병행). 앱 "가상 매수" 체크 해제 |
| `EDGE_LIVE_ORDER_KRW` | 100,000 | Edge 1회 매수 금액 상한 (MAX_ORDER_AMOUNT_KRW 보다 크면 그 값으로 제한) |
| `EDGE_LIVE_MAX_POSITIONS` | 1 | Edge 포지션 동시 보유 수 |
| `EDGE_LIVE_MAX_ENTRIES_PER_DAY` | 3 | Edge 하루 매수 횟수 |
| `EDGE_LIVE_DAILY_LOSS_KRW` | 10,000 | Edge 포지션의 그날 실현 손실 합이 이 금액에 닿으면 그날 Edge 신규 매수 중단 (0 = 사용 안 함) |

- `TRADING_STRATEGY_MODE=edge`(단독 실주문)는 그대로 둔다. 그 방식일 때 `EDGE_LIVE_ORDERS` 는 무시.
- 익절/손절/보유 시간은 기존 한 곳(`EDGE_ONLY_TP_PCT` / `SL_PCT` / `HORIZON_MIN`, 0 = `EDGE_TP_PCT` 등) 그대로.
- 확률 기준은 `EDGE_ONLY_MIN_PROB`(0 = 모델 threshold) 그대로.
- 모두 r003 재시작 후 적용.

### 2-2. 매수 (r003 종목 루프 + r005)

- 순서: 규칙 매수 판정 먼저. 규칙이 주문을 내지 않은 종목(조건 미통과 / 규칙 매매 꺼짐 / 재진입 관찰)만 Edge 판정으로 넘어간다.
- Edge 판정은 **새 BuyContext** 로 `check_buy_conditions(ctx, EDGE_LIVE_BUY_CONDITIONS)`:
  - _001~_008 (진입 시간 / 워밍업 / 쿨다운 / 중복 / 미청산 노출 / 손절 재진입 / 일일 손실 한도 / 전체 동시 보유 상한) - 규칙과 같은 함수, 전체 한도는 둘이 합쳐서
  - `_e08a_edge_live_limits` (신규): Edge 동시 보유 / 하루 횟수 / 하루 손실 한도, ETF·ETN 제외(EDGE_ONLY_EXCLUDE_FUNDS), 당일 Edge 손절 종목 재매수 금지
  - `_e09_edge_ai_signal` (기존: 정규장만, 1분 하이브리드 트리거 + 모델 확률, 모델 없음/오류는 매수 안 함)
  - _023~_025 (수량 / 현재가 신선도 / 호가 + 예약). 수량은 `min(_023 수량, EDGE_LIVE_ORDER_KRW / 현재가)`, 0주면 매수 안 함
- 규칙 판정이 남긴 상태(연속 확인, 같은 봉 중복, traded_today 예약)를 Edge 판정이 건드리지 않게 한다: Edge 쪽은 자기 상태 사본/전용 dict 사용.
  규칙이 예약만 하고 주문을 안 낸 경우의 예약 해제는 지금 코드 그대로.
- 대상: 감시목록 종목만(시세·호가를 r003 이 직접 받는 종목). 수집기 종목(틱 파일)과 NXT 세션은 실주문 대상 아님.
- 직접(MTS) 보유 종목, 규칙 매매 보유 종목, 주문 보류(A2) 종목은 Edge 가 사지 않는다(보유/대기면 매수 분기에 오지 않음).
- 주문: `api.place_buy_order(..., buy_detail="EDGE_LIVE ...", strategy="edge")`. 체결 뒤 포지션에 `strategy="edge"` 저장.

### 2-3. 포지션 표시

- `positions[code]["strategy"]` = "edge" | "rule"(없으면 rule). `positions_meta`(live_state)에 저장해 재시작·계좌 동기화 뒤에도 유지
  (tp1_done 등과 같은 방식). 전량 매도되면 지워진다.
- 표시가 없는 예전 포지션, 직접 매수분이 섞인 포지션은 rule 로 본다.
- 미체결 매수 주문(pending)에도 strategy 를 실어 체결 확정 때 포지션으로 옮긴다. 재시작으로 pending 이 사라진 경우(A2 보류로 넘어감)는
  표시를 잃을 수 있다 -> A2 보류 기록에 strategy 를 같이 남기고, 해제 때 계좌에 그 종목이 있으면 표시 복원.

### 2-4. 매도 (r006)

- `active_sell_conditions()` 를 포지션 기준으로: `sell_conditions_for(pos)`.
  - AUTO_SELL_MODE stop_only / off: 지금처럼 전역 우선(Edge 포지션도 순손익 손절만 / 자동 매도 없음).
  - AUTO_SELL_MODE all + `pos.strategy == "edge"`: `EDGE_SELL_CONDITIONS`(익절 / 손절 / 시간 상한). 적응형 엔진·규칙 매도 조건은 쓰지 않는다.
  - 그 밖: 지금과 같음.
- 당일 강제 청산(15:20)은 Edge 포지션도 대상(지금 코드 그대로).
- Edge 포지션에는 규칙 매매 부가 기능을 적용하지 않는다: 피라미딩 추가 매수, 재진입(reentry) 한도 회계, 적응형 청산 shadow 기록.
- Edge 손익은 일일 손실 한도(_007, 전체)에도 지금처럼 합산되고, 따로 `edge_live` 누계(하루 매수 횟수 / 실현 손익 / 손절 종목)를 live_state 에 둔다.

### 2-5. 가상 매매 러너와의 관계

- `EDGE_LIVE_ORDERS=True` 이면 러너(r022)는 "후보 기록만"(log_only)으로 돈다: 신규 가상 매수 없음, 이미 있는 가상 보유는 마감까지 청산,
  후보 기록(edge_only_candidates)은 계속. 같은 신호를 가상과 실주문으로 두 번 세지 않는다.
- 실주문 기록: 기존 거래 로그 + 사유 `EDGE_LIVE_*`, `EDGE_TP_* / EDGE_SL_* / EDGE_TIME_*`. 앱 "가상 매매" 창과는 별개(실거래 내역에 표시).

### 2-6. 앱 / 계약

- r016: 새 키 5개 get / set (허용 값·범위 검증). r017 상태에 `edge_live`(켜짐 여부, 오늘 횟수/손익, 한도) 추가.
- AutoBotH / AutoBotHtsH 제어 탭: "가상 매수" 체크 잠금 해제. 해제 시 확인 창(과거 검증 손실, 한도 값, r003 재시작 후 적용).
  하위 항목: 1회 금액 / 동시 보유 / 하루 횟수 / 하루 손실 한도. 구형 서버(키 없음)면 계속 잠금.
- 계약 문서(autoboth_local_mode_20261110.md) 갱신, 두 앱 버전 올림.

## 4. 확인할 위험

1. 포지션 표시 유실: 재시작·부분 체결·계좌 동기화·A2 보류를 거치며 strategy 가 사라지면 Edge 포지션이 규칙 매도(적응형 엔진)로 관리된다.
   -> 손절은 어느 쪽이든 걸리므로 방치되지는 않지만, 익절·시간 상한이 달라진다. 유실 경로를 테스트로 고정.
2. 한도 우회: 규칙 매수와 Edge 매수가 같은 턴에 각각 통과해 전체 보유 상한(_008)을 넘는 경우 -> 주문 직전 재확인.
3. 상태 간섭: Edge 판정이 규칙 판정의 연속 확인·중복 방지 상태를 바꾸는 경우.
4. AUTO_SELL_MODE=stop_only / off 에서 Edge 를 켜면 익절·시간 청산이 없다 -> 그 조합이면 Edge 실주문을 켜지 않는다(시작 때 경고 로그 + 매수 차단).
5. 같은 종목을 규칙 매매가 판 직후 Edge 가 다시 사는 경우(쿨다운 _003 / 손절 재진입 _006 이 방식과 무관하게 적용되는지).
6. 일일 손실 서킷브레이커와 Edge 전용 손실 한도의 중복 집계.
7. dry-run: 주문 없이 로그만, 누계·표시는 실계좌 파일에 쓰지 않음.

## 6. Codex 계획 검토 (2026-11-25) 반영 - 계획 v2

판정: 보완 후 진행. Claude(실무) 확인: 아래 지적은 코드와 맞다. 특히 "어느 쪽이든 손절은 걸린다"(4절 1번)는 틀린 전제였다 -
전일 보유, 감시목록 제외, 3분봉 없음·워밍업 부족이면 매도 평가 전에 건너뛴다.

보완 (v1 을 덮어씀)
1. 전략 귀속은 체결 단위로: 제출 의도(A2 선기록)에 strategy 와 진입 ID 를 남기고, 주문번호가 확인되면 r023 등록부(주문일+번호)에 strategy 를 싣는다.
   Edge 잔량·원가는 "Edge 주문의 체결"로만 계산한다(계좌 평균단가는 종목 단위라 직접 추가 매수가 섞이면 쓸 수 없다).
   첫 부분 체결부터 Edge 로 평가돼야 하므로 체결 확정(_confirm_pending_buy)이 아니라 pending 단계부터 표시한다. 변경 파일에 r023 추가.
2. 미확정·혼합 상태: 접수 불명, 귀속 미확정, Edge 보유 종목에 직접 매수가 섞인 경우 -> Edge 신규 매수 중단 + 로그/알림.
   Edge 청산 수량은 확인된 Edge 잔량까지만(직접 보유분은 팔지 않는다 - r023 원칙 그대로).
3. Edge 청산은 감시목록·3분봉 준비 여부에 의존하지 않는다: Edge 잔량이 있는 종목은 현재가만으로 익절/손절/시간 상한을 평가하는 전용 경로.
4. 한도는 두 방식이 같은 곳에서 확인: 보유·미결·제출 의도·귀속 미확정을 합쳐 전체 슬롯을 세고, 첫 주문 전에 예약한다. 분리하는 것은
   신호·연속 확인 상태뿐. 규칙 쪽이 이미 제출을 시도한 종목(응답 불명 포함)은 같은 턴에 Edge 로 넘기지 않는다.
5. 1회 금액 상한은 실제 주문가 기준: 1단계는 단일 지정가 주문만(분할·재호가 없음), 수량 = 상한 / 최종 지정가. 미체결 잔량은 시간이 지나면 취소.
6. 15:20 청산: Edge 는 정규장 전용. 종목별로 잔여 매수 취소 -> 매도 접수 -> 잔량 확인을 추적하고 실패하면 재시도, 마감 뒤 남으면 경보 +
   다음 거래일 시작 때 처리 대상. (지금 예약 청산은 done_1520 을 종목 검사 전에 세워 한 번만 시도한다.)
7. 재진입 회계: 재진입 shadow 분기가 주문 없이도 쿨다운·traded_today 를 바꾼다 -> Edge 판정은 그 분기 앞에서 갈라야 하고,
   Edge 매도 체결이 규칙 재진입 손익(reentry_state)을 갱신하지 않게 한다. 적응형 shadow 의 observe() 도 Edge 포지션 제외.
8. 기존 `TRADING_STRATEGY_MODE=edge`(단독)에서 넘어올 때: 표시 없는 잔고의 방식을 알 수 없다 -> 잔고·미결 주문이 없을 때만 전환 허용.
9. 조건 표시(r015 내보내기 / r016 conditions)도 방식별로.
10. 설정 검증: r016 set 은 타입만 본다 -> 양수 범위와 조합(EDGE_LIVE_ORDERS 는 AUTO_SELL_MODE=all 일 때만, Edge 잔량·미확정 매수가 있는 동안
    stop_only / off 전환 차단)을 r016 과 r003 시작 때 둘 다 확인. EDGE_LIVE_ORDERS=False 는 신규 주문만 멈추고 보유분의 Edge 청산은 유지.
11. 손실 한도: 확인된 Edge 매도 체결의 비용 포함 실현 손익을 체결 증분으로 한 번씩 집계. 한도 0(사용 안 함)은 1단계에서 허용하지 않는다.
    "신규 진입 중단 기준"이지 최대 손실 보장이 아니다.

Codex 권고 (사용자 결정 5절): 1 = 1회 10만원 / 동시 1종목 / **하루 1회** / 손실 1만원, 2 = AUTO_SELL_MODE=all 에서만 + bot_only 유지,
3 = 실주문이 실제로 켜진 동안만 가상 매매를 후보 기록으로.

## 8. 1~3단계 구현 결과 (2026-11-25, Codex 코드 검토 10회 - 10차 Not blocking)

계획 v2 와 달라진 점
- 포지션 메타에 strategy 를 두지 않았다. 귀속은 체결 장부(r023)의 주문 단위: Edge 매수 주문은 등록부에 strategy="edge", Edge 수량·원가는
  `state["edge"]`(종목별 매수 주문 묶음 lots)로 그 주문의 체결로만 바뀐다. r006(규칙 매도 조건)과 r005 는 바꾸지 않았다.
- Edge 종목(Edge 수량 > 0 또는 미종결 Edge 매수 주문)은 r003 종목 루프 맨 앞에서 `_edge_live_manage` 로 갈린다 - 규칙 경로
  (HOLD SKIP, 매도 조건, shadow, 규칙 매수, 예약 청산, 재진입 회계)가 Edge 종목을 보지 않는다.

동작 요약
- 매수: 규칙 매수가 주문을 내지 않은 종목만, 1분봉당 1회 `EDGE_BUY_CONDITIONS` 판정. 14:50(`EDGE_LIVE_ENTRY_END`) 이후 없음.
  주문 = KRX 매도1호가 단일 지정가, 수량 = min(상한들) // 주문가, 20초 안에 안 찬 잔량은 취소(재주문 없음).
- 신규 매수 중단 조건(`edge_live_block_reason`): 하루 횟수 / 동시 보유 / 하루 실현 손실 / 그날 손절 종목 / 주문 보류(A2) 중 /
  Edge 종목에 직접 보유분이 섞임 / 매도 가격을 몰라 손익 미상 / 체결 장부 없음·손상.
- 청산: 현재가와 Edge 원가로 손절 / 익절 / 시간 상한, 15:20 부터는 매 턴 청산 시도(가격·원가 없이도). Edge 매수 주문이 열려 있으면
  잔량 취소가 확인된 뒤 판다. 원가를 모르면(가격 없는 체결이 섞임) 익절·손절은 보류하고 시간 상한·15:20 청산만.
- Edge 매도는 자동 매도 대상(scope)과 무관하게 주문 직전에 계좌와 체결을 다시 읽고 Edge 수량으로 제한. 계좌 응답에 그 종목의
  금일 매수·매도 수량이 없으면 내지 않는다(계좌가 그 필드를 아예 주지 않는 환경은 대조 없이 진행 + 로그).
- 주문 종결: 주문번호가 정확히 맞는 상태 조회 또는 체결 장부의 종결로만(계좌 수량 변화만으로는 닫지 않음).
- 재시작: Edge 주문은 보류 기록에 strategy / 주문기관번호 / 거래소가 남고, 이전 r003 이 열어 둔 오늘의 Edge 매수는 잔량 취소를
  보류가 풀릴 때까지 재시도.
- `EDGE_LIVE_ORDERS=True` 인 동안 가상 매매(r022)는 후보 기록만.

알아둘 동작
- 접수 여부를 모르는 Edge 매수(주문번호 없음)가 실제로 체결되면 그 수량은 "직접 몫"이 된다(자동 매도 안 함, 그날 횟수는 사용된 것으로).
- AUTO_SELL_SCOPE=all 에서는 Edge 매도 뒤 같은 종목에 남은 직접 보유분이 규칙 경로로 돌아간다(scope=all 의 기존 의미).
- AUTO_SELL_MODE 가 all 이 아니거나 EDGE_ONLY_MODE 가 paper 가 아니면 신규 Edge 매수는 없다. 이미 가진 Edge 수량은 그 설정과 무관하게 항상 Edge 규칙(손절 / 익절 / 시간 상한 / 15:20)으로 청산한다 - 설정 변경·기본값 복원·초기화로 청산 규칙 없이 남지 않게(4단계 Codex 검토 반영).
