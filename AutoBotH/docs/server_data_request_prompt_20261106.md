# 서버 데이터 요청 프롬프트: AutoBotH 주가 차트·보조지표용 수집 데이터 (2026-11-06)

> 이 문서는 서버 저장소(`auto_trading_src`) 담당 코딩 에이전트(또는 개발자)에게 그대로 주는 프롬프트다.
> AutoBotH(윈도우 PC의 Electron 앱, SSH/SFTP로 서버를 읽음)는 v2.1.0_005부터 타임라인 탭에 **주가 차트**(틱봉·분봉·일봉·주봉·월봉)와
> **보조지표**(볼린저, 일목균형표, RSI, MACD, ADX)를 그린다. 지금은 서버에 이미 있는 파일만 읽어서 그리고 있고, 아래 요청이 없어도 앱은 계속 동작한다.
> 아래 항목은 "지금 데이터로는 틀리거나 부족한 부분"을 서버 쪽에서 채워 달라는 요청이다. 우선순위(P1 > P2 > P3) 순서로 처리하면 된다.

## 0. 앱이 지금 읽는 것 (변경하지 말 것 / 바꾸면 알려 줄 것)

| 용도 | 경로 | 앱이 쓰는 열 |
|---|---|---|
| 틱봉, 분봉 | `runtime/data/ticks/YYYYMMDD/<code>.csv` | `bsop_date`, `trade_time`, `price`, `cntg_vol` (헤더 이름으로 찾음) |
| 분봉 대체 (틱 파일 없을 때) | `runtime/data/YYYYMMDD/<code>_<name>_10s.txt` | `datetime`, `open/high/low/close/volume`, `raw_bar=1` 행만 |
| 일·주·월봉 | `runtime/data/YYYYMMDD/<code>_<name>_daily.csv` (그 날짜 폴더, 없으면 직전 폴더) | `date`, `open/high/low/close/volume` |
| 지표 예열 | 직전 거래일 폴더의 같은 파일들 | 위와 같음 |

- 앱은 위 파일을 **SFTP로 읽기만** 한다. 파일 이름 찾기에 `cd runtime/data/YYYYMMDD && ls -1 -- <code>_*` 한 번을 쓴다.
- 보조지표는 앱이 직접 계산한다. 공식과 기간은 `live_trading/r002_strategy_core_shared.py`의 `calculate_indicators()`, r001 값
  (BB 20/2.0, RSI 14 Wilder + 시그널 6, MACD 5/12/4, ADX 7)과 같게 맞췄고, `data_simulation/shared/indicators.py` 출력과 1e-6 이내로 일치함을 확인했다.
  일목균형표는 봇이 쓰지 않아 표준값 9/26/52를 쓴다.
- 이 경로·열 이름·r001 상수 이름을 바꿀 때는 AutoBotH 담당에게 알려 달라.

## 1. 서버 쪽 제약 (반드시)

1. r003 매매 루프와 g011 틱 수집기에 부하를 주지 않는다. 무거운 집계는 수집 시점이나 장 마감 후 배치에서 하고, 앱 요청 시점에는 미리 만든 파일을 읽기만 하게 한다.
2. 새로 만드는 파일은 저장소 밖 `runtime/` 아래에 둔다(git에 넣지 않는다).
3. 새 명령을 만든다면 `r016_control.py`와 같은 규칙: 읽기 전용, stdout에 JSON 하나, 종료 코드 0/2, 30초 안에 끝남.
4. 주문 API·KIS 토큰·계좌 정보는 이 작업과 무관하다. 건드리지 않는다.

## P1. 지금 차트가 틀리거나 비는 부분

### P1-1. 틱 파일의 체결 구분(시장·세션) 열

- 현상: `ticks/20261105/003490.csv`에 08:30:05부터 체결이 있고(장 시작 전), 마지막 체결은 15:30:11 30,350원이다.
  그런데 같은 날 `20261105/003490_대한항공_daily.csv`의 20261105 행은 시 31,000 / 고 31,700 / 저 29,550 / **종 30,100**이다.
  시·고·저는 09:00~15:30 틱과 정확히 일치하지만 종가가 다르다. `hour_cls_code`는 전 행이 0이라 구분에 쓸 수 없다.
- 확인 요청:
  1. 틱 파일에 넥스트레이드(NXT) 체결이 섞여 있는가? 08:30~08:59 체결은 무엇인가(NXT 프리마켓 / KRX 장전 시간외)?
  2. 일봉 종가 30,100과 15:30:11 틱 30,350 중 r003·g002가 기준으로 삼는 값은 무엇인가?
- 요청: 틱 CSV에 열 2개를 **끝에** 추가(기존 열 순서 유지).
  - `venue`: `KRX` | `NXT`
  - `session`: `pre`(장전) | `regular`(09:00~15:20 접속매매) | `close_auction`(15:20~15:30 동시호가) | `post`(장후)
- 앱 쪽 효과: 일봉 당일 봉 생성과 분봉에서 정규장만 고를 수 있다(지금은 시각 09:00~15:31로 자르는 임시 처리).

### P1-2. 10초 파일의 형식 설명 (또는 진짜 1분봉 파일)

- 현상: `_10s.txt`는 1분봉을 10초 간격으로 보간한 파일로 보인다(`raw_bar=1`이 1분마다 1행, 나머지는 보간값. 예: 57,767처럼 호가 단위에 맞지 않는 값).
  `volume`이 651.8, 231.3처럼 소수라 단위를 알 수 없다.
- 확인 요청: `raw_bar=1` 행의 시각은 봉 **시작**인가 **끝**인가? `volume` 단위는 무엇인가(주, 천 주, 보간 후 평균)?
- 요청(둘 중 하나):
  - (a) 위 두 가지를 이 파일을 만드는 스크립트 주석과 이 문서 답변으로 알려 준다. 또는
  - (b) 진짜 1분봉 파일을 따로 만든다: `runtime/data/bars_1m/YYYYMMDD/<code>.csv`,
    열 `ts,open,high,low,close,volume,amount,venue,session` (`ts` = 봉 시작 시각 KST `YYYY-MM-DDTHH:MM:00`, `volume` = 주).
    대상은 10초 파일과 같은 전 종목이면 좋고, 최소한 당일 감시목록·보유 종목.

### P1-3. 틱 보관 기간과 대상

- 현상: `runtime/data/ticks/`에 최근 5일(20261030~20261105)만 있고, 하루 약 22종목(감시목록 + 보유로 보임)만 있다.
  그래서 지난 날짜나 감시목록 밖 종목은 틱봉을 그릴 수 없고, 분봉은 10초 파일로 대신한다.
- 확인 요청: 보관 기간과 수집 대상을 정하는 곳(스크립트/상수)과 현재 값.
- 요청: 틱 원본은 **최소 20거래일** 보관(용량이 문제면 5일 이후 gzip 압축: `<code>.csv.gz` - 앱이 읽도록 맞추겠다).
  P1-2 (b)의 1분봉 파일이 있다면 1분봉은 더 길게(60거래일 이상) 보관.
- `ticks/YYYYMMDD/` 안의 `_collector...` 같은 비종목 파일 이름 규칙을 알려 달라(앱은 `^\d{6}\.csv$`만 종목으로 본다).

## P2. 봇이 보는 값과 앱 화면을 일치시키기

### P2-1. r003이 쓰는 분봉 프레임과 예열 범위

- 확인 요청:
  1. r003의 매수/매도 조건이 지표를 계산하는 봉 크기(1분봉, 3분봉, 120틱 등)와 각 조건이 어느 프레임을 쓰는지.
  2. 장 시작 직후 지표 계산에 **전일 봉**을 포함하는가(포함한다면 몇 봉)? 앱은 지금 전일 120봉을 예열로 붙여 계산한다.
- 앱이 코드에서 확인한 것 (맞는지 확인 부탁):
  - 예열은 `r012_prior_day_warmup.load_prior_day_warmup()` - 전일 10초 파일의 원본 1분봉 마지막 `PRIOR_DAY_WARMUP_MINUTES`(180)개, VWAP/OBV/OBV_MA는 당일만.
    앱도 같은 범위로 계산한다.
  - 3분봉은 `resample("3min", label="right", closed="right")`(구간 (t-3분, t], 끝 시각 라벨)로 만든다. 앱은 HTS 관례대로 [t, t+3분) 시작 시각 라벨로
    묶고 있어 3분봉 경계가 1분 어긋날 수 있다. 장중 실시간 3분봉도 같은 규칙인지, 10초 파일 `raw_bar=1` 행 시각이 시작인지 끝인지(P1-2)와 함께 알려 주면
    앱의 분봉 집계를 봇과 같게 맞추겠다.
- 요청: 위 내용을 `r016_control.py conditions` 출력의 각 조건에 `frame` 필드(예: `"1m"`, `"3m"`, `"tick120"`, `"daily"`)로 넣어 준다.
  앱은 조건 노드에서 해당 프레임으로 차트를 바로 열 수 있게 하겠다.

### P2-2. 봇이 계산한 지표 값 내보내기 (읽기 전용)

- 목적: 앱이 공식을 복제하는 대신, 봇이 실제로 판단에 쓴 값을 그대로 보여 준다(공식·데이터 차이로 생기는 오해 방지).
- 요청: `r016_control.py indicators --date YYYYMMDD --code CODE --frame 1m|3m|daily [--last N]`
  ```json
  {"frame": "3m", "params": {"BB_PERIOD": 20, "RSI_PERIOD": 14, "...": 0},
   "columns": ["ts","open","high","low","close","volume","BB_MIDDLE","BB_UPPER","BB_LOWER","RSI","RSI_SIGNAL","MACD","MACD_SIGNAL","MACD_HIST","DI_PLUS","DI_MINUS","ADX"],
   "rows": [["2026-11-05T09:03:00", 31000, 31700, 30600, 30650, 412300, 30825.0, "..."]]}
  ```
  - r003이 메모리에 가진 프레임을 그대로 쓰지 말고(매매 루프 간섭 금지), 같은 함수(`calculate_indicators`)를 같은 입력 파일로 다시 돌려서 만든다.
  - 숫자는 소수 6자리 이하, 결측은 `null`.

## P3. 전송량·편의

### P3-1. 서버 쪽 봉 집계 명령 (선택)

- 현상: 감시 종목 틱 파일은 하루 5MB 안팎(003490: 57,943체결, 5.3MB)이라 첫 로드에 LAN에서도 약 5초, Cloudflare 터널로는 더 걸린다.
  당일 파일은 앱이 바이트 오프셋으로 이어 읽어 두 번째부터는 빠르다.
- 요청(P1-2 (b) 1분봉 파일이 생기면 우선순위 낮음):
  `r016_control.py bars --date YYYYMMDD --code CODE --kind tick|min|day|week|month --n N [--warmup 120] [--since-ts ISO]`
  ```json
  {"source": "ticks", "columns": ["t","o","h","l","c","v"], "bars": [["2026-11-05T09:00:00", 31000, 31700, 30600, 30650, 412300]],
   "warm": [], "warm_date": "20261104", "next_since": "2026-11-05T15:30:11"}
  ```
  - `--since-ts`가 있으면 그 이후 봉만(마지막 봉은 갱신될 수 있으므로 포함) 돌려준다(장중 10초 폴링용).
  - 매 요청마다 5MB를 파싱하지 않도록 날짜·종목별 집계 캐시(`runtime/cache/bars/`)를 쓴다. Pi CPU 사용량을 측정해 결과에 적어 달라.

### P3-2. 일봉 이력 파일 하나로 (용량)

- 현상: 날짜 폴더마다 전 종목(약 3,290종목)의 `_daily.csv`(각 200행)를 다시 써서 폴더 하나가 약 1.1GB다. 앱은 그중 한 종목 파일 하나만 읽는다.
- 요청: 종목별 일봉 이력을 한 파일로 유지(`runtime/data/daily_history/<code>.csv`, 장 마감 후 1행 추가), **최소 3년**.
  주봉·월봉이 지금은 43봉·11봉뿐이다. 기존 날짜 폴더 파일은 g002/백테스트가 쓰면 그대로 두어도 된다(앱은 새 파일이 있으면 그것을 먼저 읽겠다).

### P3-3. 틱 수집기 상태를 `status`에

- 목적: r003은 틱 파일이 없으면 진입을 보류한다(`TICK_ABSTAIN_NO_FILE`). 수집기가 멈추면 앱 제어 탭에서 바로 보이게 한다.
- 요청: `r016_control.py status`에 블록 추가
  ```json
  "collector": {"running": true, "pid": 1234, "started_at": "2026-11-05T07:07:01",
                "symbols": 23, "last_write": "2026-11-05T15:30:11", "stale": [{"code": "161390", "last_write": null}]}
  ```
  `stale` = 감시목록·보유 종목 중 최근 60초(장중) 동안 기록이 없는 종목.
