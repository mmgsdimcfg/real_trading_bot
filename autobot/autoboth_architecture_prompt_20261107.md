> 이 문서는 윈도우 PC의 AutoBotH(Electron + React, `ssh2`) 저장소에서 일하는 코딩 에이전트에게 그대로 주는 프롬프트다.
> 기능 명세는 이미 받은 문서가 기준이다. 이 문서는 그 위에 **역할 분담 원칙**과 **서버(라즈베리파이 4B) 부하 규칙**을 정하고,
> 지금 코드가 규칙을 지키는지 점검·수정하게 한다.
> - `condition_viewer_implementation_prompt_20261104.md` - 로그 문법, 파이프라인 뷰어, SSH 설정
> - `autoboth_control_implementation_prompt_20261105.md` - `r016_control.py` 제어 CLI(status/start/stop/set/watchlist/collector)
> - `autoboth_chart_data_reply_20261106.md` - 차트 데이터(`indicators`, `bars`)

## 0. 당신의 임무

1. 아래 1장의 역할 분담을 코드에서 확인한다. 어긋나는 곳(앱이 판단 로직을 복제하거나, 서버 파일을 직접 쓰거나, 앱이 꺼지면 매매가 멈추는 의존)을 찾아 고친다.
2. 2장의 **서버 부하 예산**을 지키도록 SSH 연결, 로그 읽기, 폴링 주기를 정리한다. 이번 작업의 핵심이다.
3. 3장의 연결 끊김·재연결 동작을 구현하거나 점검한다.
4. 변경 내역과 테스트 결과를 5장 형식으로 보고한다.

새 기능을 추가하는 작업이 아니다. 기존 기능은 그대로 두고 구조와 부하만 정리한다.

## 1. 역할 분담 (확정된 구조)

```
 ┌──────────── 라즈베리파이 4B (Ubuntu, 24시간) ───────────┐        ┌──── 윈도우 11 (켜져 있을 때만) ────┐
 │ systemd --user autobot-r003.service                   │        │ AutoBotH (Electron)                 │
 │   r003 실매매 (KIS API, 토큰, 계좌, live_state)        │        │  - 상태/파이프라인/차트 표시         │
 │   └ g011 틱 수집기 (cron g022가 감시)                  │  SSH   │  - 실행/정지/재시작 버튼            │
 │ 로그: runtime/log/YYYYMMDD/*.log (append-only)         │◀──────▶│  - 설정값/감시목록 편집 요청         │
 │ 제어 CLI: live_trading/r016_control.py (JSON 출력)     │        │  - 판단 로직 없음, 주문 없음         │
 │ cron: g001/g002 스캔, g015 Edge AI 재학습 등           │        └─────────────────────────────────────┘
 └───────────────────────────────────────────────────────┘
```

- **매매의 주체는 서버 하나뿐이다.** 앱을 끄거나 SSH가 끊겨도 r003은 계속 돈다. 앱이 꺼져 있다는 이유로 서버에 어떤 동작도 일어나면 안 된다.
- **앱은 표시와 요청만 한다.** 읽기는 로그 파일 증분 읽기와 `r016_control.py` 읽기 명령, 쓰기는 `r016_control.py` 쓰기 명령뿐이다.
  - 서버 파일을 SFTP로 쓰거나 지우지 않는다.
  - KIS API, 토큰, 계좌 파일(`~/KIS/config`)에 접근하지 않는다.
  - 매수/매도 조건 판정을 앱에서 다시 계산하지 않는다. 로그와 `conditions` JSON에 나온 결과를 그대로 보여준다.
- **r003은 윈도우에서 실행하지 않는다.** KIS 계정·토큰이 하나이고, live_state·cron·Edge AI가 서버에만 있다. 앱에 "로컬에서 봇 실행" 기능이 있다면 제거한다.
- 서버 재부팅 후 r003 자동 시작 여부는 서버 쪽 설정이다(지금은 자동 시작 안 함). 앱은 `status`를 보고 "정지됨 - [실행]"만 안내한다.

## 2. 서버 부하 예산 (라즈베리파이 4B: 4코어, RAM 4 GB, 장중 r003 + g011 동작)

서버에서 측정한 비용(2026-11-07):

| 동작 | 비용 |
|---|---|
| `r016_control.py status` | 약 2.1 초 CPU, Python 프로세스 약 70 MB (pandas import 포함) |
| `r016_control.py conditions` / `schema` | 약 1.5 초, 약 70 MB |
| `indicators` / `bars` | 수 초(첫 호출), 이후 캐시로 짧아짐 |
| SFTP `stat` + 증분 읽기 | 거의 0 (Python 미기동) |
| 하루 메인 로그 | 5~10 MB, 5~9만 줄 |

RAM 여유가 1 GB 안팎이고 earlyoom이 동작 중이다. **Python 프로세스를 자주 띄우는 것이 가장 큰 부담**이다. 아래 규칙을 지킨다.

### 2.1 SSH 연결
- 앱 전체에서 **SSH 연결 1개를 유지**하고, SFTP 세션 1개와 exec 채널을 그 위에서 연다. 호출마다 새로 접속하지 않는다.
- keepalive: `keepaliveInterval` 15초, `keepaliveCountMax` 4.
- exec는 **동시에 1개만**(직렬 큐). 쓰기 명령뿐 아니라 읽기 명령(`status`, `conditions`, `bars`, `indicators`)도 같은 큐로 보낸다.
  큐에 같은 읽기 명령이 이미 대기 중이면 새로 넣지 않는다(중복 제거).

### 2.2 로그 읽기 (가장 자주 일어나는 동작)
- SFTP `stat` → 크기가 늘었을 때만 `createReadStream({start: offset})`. 바이트 오프셋 증분 읽기만 허용한다.
- `tail -f`를 exec로 띄우는 방식도 허용하지만, 앱 재연결 때 고아 프로세스가 남지 않게 채널 종료 시 정리를 확인한다. 둘 중 하나만 쓴다.
- 과거 날짜는 1회 전체 읽기 후 캐시(윈도우 로컬 디스크). 같은 파일을 다시 처음부터 읽지 않는다.
- 파싱은 윈도우 쪽 워커 스레드에서 한다. 서버에서 `grep`/`awk`로 미리 거르는 exec를 폴링마다 띄우지 않는다.

### 2.3 폴링 주기

| 대상 | 주기 | 비고 |
|---|---|---|
| 오늘 메인 로그 증분 | 5~10초 (설정값) | SFTP만 사용 |
| 로그 디렉터리 목록 (재시작으로 새 로그 파일 생김 감지) | 30초 | SFTP `readdir` |
| `r016 status` | **30초** (기존 10초에서 변경) | 창이 최소화/백그라운드면 120초. 제어 동작 직후에는 2초 간격으로 최대 90초 |
| `conditions` | 앱 시작 1회 + 설정 저장 후 1회 + 수동 새로고침 | 폴링 금지 |
| `schema --all` | "고급: 전체 설정값" 화면을 열 때만 | 폴링 금지 |
| `bars --since-ts` | 차트 창이 **보이는 동안만** 10초, 종목 1개 | 차트 여러 개를 동시에 폴링하지 않는다(보이는 것 1개만) |
| `indicators` | 차트 종목/주기 바꿀 때 1회, 이후 60초 | |

- 장 마감 후(15:40 이후)와 장 시작 전(08:00 이전)에는 로그 증분 30초, `status` 120초로 늦춘다. 시각 판단은 서버 KST(로그 시각 또는 `status.generated_at`) 기준.
- 사용자가 앱 창을 최소화하면 차트 폴링을 멈춘다.
- 이 표의 주기는 설정 탭에서 바꿀 수 있게 하되, 하한(`status` 15초, `bars` 5초)을 둔다.

### 2.4 서버 쪽에 예정된 개선 (앱은 대비만)
서버 저장소에서 `r016 status`가 pandas를 불러오지 않도록 지연 import를 적용할 예정이다(적용되면 약 1초 이하). 적용 전후 응답 JSON 형식은 같다.
앱은 위 주기를 그대로 쓰면 된다.

## 3. 연결 끊김과 재연결

- 끊김 감지 시: 상단 상태바 "서버 연결 끊김 - 봇은 서버에서 계속 동작 중일 수 있음" 표시. 마지막으로 받은 상태는 회색으로 남긴다.
- 재연결: 2초, 5초, 10초, 30초, 이후 60초 간격(지수 백오프). 재연결 성공 시 저장해 둔 오프셋부터 로그를 이어 읽고 `status`를 1회 호출한다.
- 쓰기 명령(`start`/`stop`/`restart`/`set`/`watchlist set`) 실행 중에 끊기면 결과를 모르는 상태다. **자동으로 다시 보내지 않는다.**
  재연결 후 `status`/`history -n 5`로 실제 결과를 확인해 사용자에게 보여준다.
- 서버 재부팅(SSH 호스트 키 동일, `status.service.active_state`가 `inactive`)이면 "서버가 재시작되어 봇이 정지됨 - [실행]" 안내.

## 4. 점검 체크리스트 (코드에서 확인하고 결과를 표로 보고)

1. `ssh2` Client 생성 지점이 몇 곳인가? 1곳으로 줄였는가?
2. exec 호출이 모두 직렬 큐를 거치는가? 같은 읽기 명령 중복 제거가 되는가?
3. 로그 읽기가 바이트 오프셋 증분인가? 파일 전체를 다시 읽는 경로가 남아 있지 않은가?
4. `status` / `conditions` / `bars` / `indicators` 호출 주기가 2.3 표와 같은가? 창 최소화·장외 시간 감속이 되는가?
5. 앱에 r003 판단 로직 복제, KIS 호출, 서버 파일 직접 쓰기, 로컬 봇 실행 코드가 남아 있는가?
6. 끊김 중 쓰기 명령 자동 재전송이 없는가?

1. **[필수] 서버 코드 경로 고정값.** `src/shared/control.ts:173`(`buildR016Command`)와 `src/main/conditions.ts:40`(`fetchR015`)이

   - 상수 하나(`SERVER_CODE_SUBDIR = 'real_trading_bot/autobot'`, `src/shared/control.ts`)로 모으고 두 곳이 그것을 쓰게 한다.
     설정 화면에 고급 항목으로 노출해도 된다(기본값 = 위 상수).
   - 지금은 서버에 임시 심볼릭 링크 `/data/srv/autobot/auto_trading_src -> real_trading_bot/autobot`이 있어서 기존 빌드도 동작한다.

4. **[권장]** `keepaliveCountMax` 3 → 4(2.1). 장외 시간(15:40~08:00) 로그 폴링 30초 감속(2.3).
5. 서버 쪽 대응 예정: `r016 status`에서 pandas 지연 import(1초 이하로 단축). 응답 형식 변화 없음.
